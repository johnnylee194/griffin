# 运势功能 Feature Spec

> 状态：v0.4
> 更新日期：2026-05-07

---

## 1. 方向与目标

### 核心定位
以**八字黄历**为中心，提供麻将相关的个性化运势解读。不追求科学性，追求「看起来专业、读起来有意思、用起来有参考价值」。

### 设计原则
- **专业感**：八字、神煞、宜忌等传统元素
- **个性化**：基于用户八字，不是通用模板
- **麻将相关**：所有内容围绕打牌场景，不谈婚丧嫁娶
- **秒出骨架 + AI 补 narrative**：结构化数据秒出，AI 解读在后台生成

---

## 2. 数据需求

### 用户字段扩展

| 字段 | 类型 | 说明 | 必填 |
|------|------|------|------|
| `birth_date` | TEXT | 出生日期（YYYY-MM-DD） | 已存在 |
| `birth_time` | TEXT | 出生时辰（如 "14:30"） | **新增，强制** |
| `birth_location` | TEXT | 出生地点（城市名，如"成都"） | **新增，强制** |
| `birth_latitude` | REAL | 出生地纬度（由城市名 geocoding 得到，缓存） | **新增，缓存** |
| `birth_longitude` | REAL | 出生地经度（由城市名 geocoding 得到，缓存） | **新增，缓存** |
| `gender` | INTEGER | 性别（0: 女 / 1: 男，用于乾造/坤造） | **新增，强制** |

> `birth_latitude` 和 `birth_longitude` 在用户保存出生地时通过 geocoding 服务获取，存储用于真太阳时计算，避免每次实时查询。

### 真太阳时计算
- 使用 `birth_location` 的经纬度
- 计算公式：当地平太阳时 = 北京时间 ± (当地经度 - 120°E) × 4分钟
- 不做夏令时校正（用户通常不知道自己出生时是否夏令时）

## 3. 技术方案

### 依赖库

```
lunisolar                        # 核心库，八字计算
@lunisolar/plugin-char8ex         # 八字十神、神煞
@lunisolar/plugin-takesound      # 五行纳音
@lunisolar/plugin-thegods        # 神煞宜忌（基于《协纪辨方书》）
geocoding                        # 城市名 → 经纬度（用于真太阳时计算）
```

> 注：使用 **高德地图 API**（AMap）进行城市名 → 经纬度转换。需要 `AMAP_API_KEY` 环境变量。QPS 限制视套餐而定，已缓存结果到用户表。

### 黄历数据（lunisolar 库自带）

| 数据 | 说明 | 获取速度 |
|------|------|----------|
| 八字四柱 | 年柱、月柱、日柱、时柱 | < 1ms |
| 纳音五行 | 如「剑锋金」「山头火」 | < 1ms |
| 十神 | 比肩、劫财、正官… | < 1ms |
| 神煞 | 文昌贵人、驿马星… | < 1ms |
| 每日宜忌 | 宜打牌、忌大规模投资… | < 1ms |
| 吉神方位 | 财神、喜神、福神方向 | < 1ms |
| 凶煞方位 | 煞神方向 | < 1ms |
| 黄道黑道 | 黄道日/黑道日 | < 1ms |

### AI 用途
仅用于**生成 narrative 解读**，结构化为：
- 今日整体运势描述（3-5 句话）
- 针对麻将的具体建议
- 吉祥方位和时间段的解读
- 需要注意的警示（如有）

### 性能目标
| 阶段 | 目标 |
|------|------|
| 结构化黄历数据（lunisolar） | < 100ms |
| AI narrative 生成 | 10-30s（不可控） |
| 页面可交互时间 | < 500ms（骨架先出） |

#### Phase 3 目标：7+1 维度两屏结构

**第一屏（快速决策）**
- 今日运势总判断（旺/平/弱 + 一句话）
- 打牌策略（大注/小注/观望）
- 今天最适合做什么（麻将专项）
- 黄金时段（12时辰，当前时辰高亮）
- 最佳方位

**第二屏（深度阅读）**
- 冲煞空亡警示
- 宜忌清单
- 面相观察点
- 颜色/数字

详见 `docs/CR-DESIGN-LOOKUP-AND-FACE.md` Section 三。

### 预设问题清单

**静态问题（所有人都一样）：**
1. 「今天打牌有没有什么禁忌？」
2. 「今天适合打大牌还是小注？」
3. 「今天财神在哪个方向？」
4. 「有没有什么吉祥数字或颜色？」

**动态问题（需要用户战绩数据）：**
1. 「基于我最近的运气，今天适合翻本还是见好就收？」
2. 「我这周手风如何？有什么建议？」
3. 「我上次在[最近去过的地方]输了，今天还适合去吗？」

### 交互流程

1. 用户进入黄历 Tab
2. **立即**：展示八字日期 + 结构化黄历数据（宜忌、财神方位等）
3. **立即**：展示 AI narrative 的骨架（loading 状态）
4. **后台**：调用 AI 生成 narrative，完成后替换骨架
5. 展示预设问题列表（静态全显示，动态需要战绩数据才显示）
6. 用户点击问题 → 触发 AI 生成答案 → 展示

### 错误处理

| 场景 | 处理 |
|------|------|
| 缺少 `birth_time` | 引导用户去设置，不展示黄历 Tab |
| 缺少 `birth_location` | 引导用户去设置，不展示黄历 Tab |
| 缺少 `gender` | 引导用户去设置，不展示黄历 Tab |
| AI 生成失败 | 展示结构化数据 + 「AI 解读生成失败，请稍后重试」 |
| 网络离线 | 展示最后缓存的结构化数据 + 提示「离线，无法生成新解读」 |

## 5. 数据流

```
用户进入
    ↓
检查用户字段（birth_date + birth_time + birth_location + gender）
    ↓ 缺失 → 引导补充
    ↓ 完整
构建 lunisolar 实例（日期 = 今日，出生信息 = 用户信息）
    ↓
计算真太阳时校正
    ↓
调用 lunisolar.char8ex() 获取八字
    ↓
查询今日黄历数据（神煞、宜忌、吉神方位）
    ↓
[并行]
  ├→ 立即渲染：八字日期 + 结构化黄历（< 100ms）
  └→ AI 解读请求（prompt 含八字 + 黄历 + 用户战绩）
          ↓
      AI 返回 narrative
          ↓
      渲染 AI 解读（替换 loading 状态）
```

## 6. Prompt 设计

### Phase 2 Prompt（当前实现）

单段落 narrative prompt，详见 `backend/src/utils/horoscope.ts` 的 `buildHoroscopePrompt`。

```
你是一位中国传统黄历解读师，专门为麻将玩家提供运势指导。

用户信息：
- 八字：[八字]
- 今日黄历：宜[xxx] 忌[xxx] 财神[方向] 喜神[方向]
- [可选]近期战绩：[战绩摘要]

请用大白话解读，不需要出现「驿马星」「财库」「命宫」等术语。

输出格式：
- 一段话描述今日整体运势（3-5句）
- 针对麻将的具体建议（2-3句）
- 如果有警示，加上提醒（1-2句）

语气：轻松但有参考价值，不要过度乐观或悲观。
```

### Phase 3 Prompt（7维度 prompt 模板）

每个维度独立 prompt，独立调用 MiniMax API（非 streaming）。

#### MiniMax API 调用规范

```typescript
// 请求体：显式禁用 thinking
const response = await axios.post(apiUrl, {
  model: 'MiniMax-M2.7',
  max_tokens: 8192,
  thinking: { type: 'disabled' },  // ← 必须显式设置
  messages: [{ role: 'user', content: prompt }]
}, { headers });

// 响应解析：只取 text blocks
const blocks: any[] = response.data.content || [];
const textBlocks = blocks.filter((b) => !b.thinking && b.type === 'text');
const fullText = textBlocks.map((b) => b.text).join('');
```

#### 四川麻将术语红线

**禁止词（任何 prompt 或 AI 输出中不得出现）：**

| 禁止词 | 正确替代 |
|--------|----------|
| 坐庄、跟牌、做牌 | 下叫、碰、摸 |
| 押注、加注、加大注 | 做大番、押大 |
| 听牌 | 下叫 |
| 胡牌 | 胡 |

**正确使用的川麻术语：**
- 下叫（听牌）、宽叫（听牌张数多）、大叫（番数高）
- 放炮（胡别人打出的牌）、自摸（自己摸到胡）
- 碰（碰牌）、摸（从牌墙摸新牌）

#### fortune prompt（今日运势）

```
你是一位中国传统八字黄历解读师，专门为四川麻将血战到底玩家提供运势指导。

用户八字：
${bazi.year}年 ${bazi.month}月 ${bazi.day}日 ${bazi.hour}时

请推导今日运势，分三步输出：

第一步：你的八字事实
- 日主是什么（如庚金），代表什么性格和牌风
- 月令旺衰（如酉月金旺），得令还是失令
- 日支状况（如辰），有没有冲破害空亡

第二步：今天的事实
- 今日日柱（如辛酉日），日主得令否
- 今日月令是什么，当令之气对日主利弊
- 今日纳音（如路旁土），能量质感

第三步：叠加推导
- 八字事实 + 今天事实 → 今天整体能量如何
- 十神如何影响牌运（偏财旺？正印稳？）
- 麻将场景：今天手风可能怎样

请在推导过程中解释所有八字术语（十神、纳音、得令、冲、破、害、空亡等），不预设用户懂八字。

结论：旺/平/弱 + 一句话核心判断 + 对打牌的具体行动建议

要求：
- 川麻术语（宽叫、大叫、放炮、自摸，碰，摸，下叫）
- 不要用"坐庄/跟牌/做牌/押注/加注"
```

#### betting prompt（打牌策略）

```
你是一位中国传统八字黄历解读师，专门为四川麻将血战到底玩家提供运势指导。

以下是你已经确认的今日运势结论：
- 运势等级：${fortuneLevel}
- 核心判断：${fortuneSummary}
- 今日要点：${fortuneHighlights || fortuneSummary}

请基于以上结论，推导今日打牌策略。

推导过程（请逐段输出）：
1. 能量水平：今天整体运势如何，有没有底气去认真打
2. 十神财运型：今天财运靠什么——偏财（运气）还是正财（技术）
3. 纳音质感：今天的能量质感是爆发型还是持续型
4. 麻将连接：运气成分、心态、资金策略

结论：[大注/小注/观望] + 一句话理由

要求：
- 不要重复 fortune 的推导，要在此基础上直接给出判断
- 川麻术语（宽叫、大叫、做大番等）
- 结论简洁有力，给出明确行动指导
```

#### bestAction prompt（麻将决策）

```
你是一位四川麻将血战到底高手，同时精通八字命理。

用户八字：${bazi}
今日运势等级：${fortuneLevel}
今日要点：${fortuneHighlights}

请针对以下5个场景，给出今日的麻将决策建议。

场景1：下叫（听牌）决策
今天适合宽叫还是大叫？先讲今天麻将场上的牌局特点，再讲八字/运势如何影响这个选择。

场景2：碰 vs 摸
什么情况下该碰牌，什么情况下该摸新牌？先讲麻将逻辑，再结合今日运势判断。

场景3：放炮 vs 自摸
遇到可以胡的牌，是放炮就胡还是贪自摸？结合今天的运势和冲煞空亡来推导。

场景4：对手方位观察
今天要重点防哪个方位的人，不怕哪个方位？结合 direction 维度的方位分析。

场景5：收官策略
牌局尾声，是乘胜追击还是见好就收？结合 goldenTime 的时段分析和 conflictWarning 的警示。

要求：
- 每个场景：结论先行（10字以内），再跟推导
- 川麻术语（宽叫、大叫、放炮、自摸，碰，摸，下叫）
- 不要用"坐庄/跟牌/做牌/押注/加注"
```

#### direction prompt（方位）

```
你是一位中国传统八字黄历解读师，专门为四川麻将血战到底玩家提供方位策略。

用户日主：${dayStemTenGod}（如庚金）
五行喜忌：${monthStemTenGod}月令

四川麻将4人座位（东南西北），用户坐在某方位时：
- 上家 = 逆时针第一家
- 下家 = 顺时针第一家
- 对家 = 正对面

座位关系（以用户坐北位为例）：
- 上家 = 东，下家 = 西，对家 = 南
- （坐东位时：上家=南，下家=北，对家=西；以此类推）

请输出：
1. 各位置策略（坐在北/东/南/西位分别怎么打）

- 用东南西北，不用"左边/右边"

```

```
- 日支害：${harming}
```

```json
      "今天整体：赢是运气，输是正常。能小赢就收，别恋战"
    ],
    "conclusion": "今日运势波动，不稳定。冲破害三重压力下，不适合冒险，大牌做好防截胡，15-19点金时辰反而不牢靠。"
  }
}
```

**prompt 设计要点：**
- 四个概念（冲、破、害、空亡）独立推导，每项都要讲清楚：是什么→为什么是这样→对打牌的具体影响
- 不要用"加大注/押大注"等词，用"做大番/押大/做大"
- 结合用户八字结构来讲，不是通用模板
- mahjongAdvice 列表给出具体麻将场景下的应对，不讲大道理
- 最后 conclusion 一句话概括核心风险

#### 维度 8 详细规范：luckEnhancement（开运清单）

开运清单 = 今天可以做的具体行动，让八字/五行能量在麻将桌上对自己更有利。不是通用风水建议，而是**从八字和今天的黄历叠加推导出来的今天特有结论**。

三个子类：**饮品**、**穿着颜色**、**饰品**。

---

**第一步：你的八字事实**

日主是什么、五行旺衰、喜忌什么。

---

**第二步：今天的事实**

今天的年月日柱是什么、五行结构是什么、哪股气最旺。

---

**第三步：叠加推导**

八字事实 + 今天事实 → 今天的核心问题是什么、哪股气是今天的救星。

---

**第四步：三类清单推导**

每个条目：事实 → 解释 → 对打牌的影响。全部从五行/八字推导出来。

| 类别 | 推导逻辑 |
|------|----------|
| 饮品 | 五行体质 + 今天五行结构 → 宜忌 |
| 穿着颜色 | 日主喜忌 + 今天当令之气 → 宜忌 |
| 饰品 | 五行材质 + 今天能量 → 宜忌 |

**不纳入的条目：**
- 数字（麻将场景无法结合八字）
- 左手/右手摸牌（摸牌顺序固定，无从选择）
- 上厕所时机（通用风水，无八字推导）
- 选座位（川麻是抽签决定）

## 9. Open Questions → 已确认

~~1. **出生地点存储格式**：存城市名还是经纬度？城市名需要额外 geocoding 库转换。~~
→ 存**城市名**，经纬度在计算时通过 geocoding 库实时转换（或缓存一份在用户表）

~~2. **历史记录保留**：是否保留每日黄历快照？保留多久？~~
→ **不做历史存储**。每天的运势是当时快照，过了就过了。用户想回顾可以截图。

~~3. **AI 生成并发控制**：同一用户同时点多个问题，是否排队还是并行？~~
→ **不允许并发**。点了一个问题，其他问题隐藏 → 显示进度 → AI 返回 → 展示结果 → 问题恢复

~~4. **用户修改出生信息后**：历史黄历是否需要重新生成？~~
→ **自动重新生成**。用户修改 birth_date / birth_time / birth_location / gender 后，触发全量重新生成
